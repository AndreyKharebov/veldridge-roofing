# Services page

Implementation of **Services — Desktop 1440**, Figma node `145:324` in the
Roofing company file. Route: `/services` (already registered in `App.jsx`).

## Structure

- `ServicesHero`: page-owned copy and photo passed to shared `PageHero`.
- `ServiceFinder`: nine real, keyboard-accessible in-page links.
- `ServiceDetail`: one reusable component for the six alternating detail rows.
- `ServiceCare`: three supporting services; each entire card links to Contact.
- `ServicesCTA`: page-owned copy and photo passed to shared `PageCTA`.
- `servicesData.js`: titles, descriptions, scope points, image imports and stable
  anchor IDs; the finder is derived from this same source, not a duplicate list.

The page uses indented Sass, BEM, the existing font/color tokens and 1280px
content area. It does not import HomePage components or page-private styles.
Shared Header/Footer remain in App. No dependency or runtime image URL is added.
The common Hero and CTA were extracted from About without changing its content.

## Navigation

All inquiry buttons and supporting-service cards route to `/contact`.
The hero's Explore Services link targets `#service-finder`. The finder targets:

`#free-inspection`, `#roof-replacement`, `#damage-repairs`, `#roof-renovation`,
`#commercial-roofing`, `#solar-panels`, `#roof-maintenance`,
`#storm-damage-restoration`, `#gutters-drainage`.

Hash navigation supports direct URLs, repeated activation, browser history,
keyboard focus and reduced motion. Existing Contact content is not changed.

## Images

Assets are local WebP copies of the approved Figma imagery (up to 1600px,
quality 90, with the original composition retained), stored next to the
owning components. Commercial and Solar are the illustrative AI images already
approved in that design; no new images are generated by this implementation.

- `ServicesHero/assets/services-hero.webp`: shaped hero photo.
- `ServiceDetail/assets/inspection.webp`, `replacement.webp`, `repairs.webp`,
  `renovation.webp`, `commercial.webp`, `solar.webp`: main service photos.
- `ServiceCare/assets/maintenance.webp`, `gutters.webp`: supporting-service photos.
  Storm restoration intentionally shares `ServiceDetail/assets/replacement.webp`,
  matching Figma.
- `ServicesCTA/assets/services-cta.webp`: aerial roof photo.

Keep filenames or update the imports in servicesData/the relevant wrapper when
replacing photos. Update alt text as needed. Hero uses the same independent SVG
mask as About, so a replacement hero image can be rectangular.

## Responsive behavior and checks

Desktop >=1101px follows the approved 1440px composition. Tablet and mobile
have working fluid fallbacks: two/one-column finder and supporting cards,
stacked details on mobile, wrapping buttons and no hover-dependent navigation.
These are implementation fallbacks, not separately approved Figma layouts.
There are no new entrance/scroll animations.

Run `npm run lint` and `npm run build`. Verify images, all nine anchor links,
Contact actions and keyboard focus at 1101, 1280, 1440 and 1920px; also check
900, 700, 390 and 320px. Compare About against its pre-extraction layout.
